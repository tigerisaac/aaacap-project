## How to read retention

An `expiresAt` value is an eligibility cutoff, not a guarantee that storage has already been erased. `cleanupShield` runs daily at 04:00 America/Chicago; audio delivery cleanup runs every five minutes. Failures, backlog and service availability can delay physical removal. These are scheduled application jobs, not an assertion that Firestore TTL policies or backup policies are configured. [Schedules](../backend/src/cloud/index.ts), [cleanup](../backend/src/cloud/store.ts).

Sensitive names, numbers, content and tokens use application encryption where specified below. Identifiers, routing state, dates and operational metadata are not all application-encrypted. Hashing does not make account-linked data anonymous. Firestore client access is denied; authenticated server routes enforce owner/helper permissions. Account deletion and per-item deletion differ from expiry.

## Draft App Privacy mapping

Apple asks for data collected by both the app and integrated partners, and treats off-device retention beyond servicing a real-time request as collection. Therefore provider retention must be checked before omitting transient audio/text. These are review inputs, not submitted answers. [Apple App Privacy details](https://developer.apple.com/app-store/app-privacy-details/).

| Current app-manifest declaration | Shield use and draft purpose |
|---|---|
| Name, Email Address, Phone Number, Contacts | Account/legacy identity, protected person, explicit contacts/caretakers and sharing labels; linked to account, App Functionality |
| User ID, Purchase History | Authentication/access and RevenueCat subscription records; linked, App Functionality and subscription Analytics |
| Device ID | APNs token linked to signed-in account; App Functionality |
| Audio Data, Emails or Text Messages, Other User Content | Call/message processing, summaries and submitted Check text; linked, App Functionality. Keep conservative disclosures until provider retention is verified. |

The app currently declares no tracking and no tracking domains; it declares the app-only UserDefaults reason `CA92.1`. The Call Directory extension declares no collection; RevenueCat contributes its own bundled manifest. The unsigned archive check found all three manifests. [App manifest](../ios/Shield/Resources/PrivacyInfo.xcprivacy), [theme archive evidence](IOS-THEME-PORT.md).

Before final answers, resolve whether operational call/use metrics and linked server diagnostics require additional **Product Interaction / Other Usage Data / Performance Data / Other Diagnostic Data** declarations and purposes. They are not currently listed in the app manifest; the bounded production sample above confirms identifier-bearing diagnostic records exist. Verify provider/SDK collection of IP, device attributes, diagnostics, any geographic derivation and retention; absence of a custom analytics SDK does not settle those questions. No evidence here establishes ad tracking, advertising use, location permission or cross-app profiling.
