# Caller self-identification and evaluation continuity

October 13, 2026. V154 is an offline subscription GPT-6 Luna medium experiment. It clarifies self-identification while retaining v153's schema shape, action mapping, charge/payment and empty-contact safeguards, evidence checks, bounded clarification and recording consistency checks. Runtime screening v134, post-call v10 and the deployed release remain unchanged.

## Development basis and size

The [v153 development review](SCREENING-SOCIAL-PURPOSE-AUDIT.md) found both a stated service role lost during a regular-bill update and an identity inferred from a third-party organization. V154 distinguishes the caller's own self-identification from the task or another entity, while allowing a brief answer to Shield's opening question. Those known development observations supply the change; public or spent fresh wording does not.

V154 has 4,447 instruction characters and 5,592 tool characters, totaling 10,039 versus v153's 9,992: 47 additional characters, or 0.47%. The unchanged greeting adds 207 characters. Its frozen request hash is `df26f312e58ff6051c3b198e05ea0163b38569b43d69c9ec237eb926e08d8d4c`. Only instruction and identity-description text changes. Local equivalence assertions verify that schema structure and inherited refinements survive the description update.

## Input isolation and local checks

Each caller starts a separate ephemeral subscription thread. Only the frozen request, fixed greeting, caller speech and that caller's native tool/question history enter inference. Labels, expected actions, case IDs and future replies remain outside target input. Existing concurrent local protocol checks verify thread isolation; inspection found no shared caller state causing the identity misses.

Both frozen requests and audit-only unions containing their actual transport greeting and fixed clarification hints have zero matching twelve-word public passages or complete short openings across all 1,044 pinned cases. An earlier broader union also passed but included the application's voice instructions instead of the subscription greeting; the corrected transport-specific check is the relevant one. Neither check rules out conceptual overfitting or unknown pretraining exposure. Public results remain repeated regressions, not unseen validation.

Its local protocol mock passes 44 requests covering evidence, schema correction, question bounds, recording consistency and immediate restricted-conduct blocks. The continuation helper passes 34 local integrity checks. Both real interrupted public prefixes pass inference-free preparation under the final source gate; eight deliberate policy/scoring/transport/runner alterations are rejected. `npm run check` passes typecheck, 203 unit tests and build; `npm run test:firebase` passes all 154 emulator tests. The application suites preceded the continuation-only runner changes, which received the separate integrity checks. Ordinary and caution runtime request hashes remain unchanged.
